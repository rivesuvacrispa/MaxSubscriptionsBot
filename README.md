1. Логика подписки

При входе бот показывает пользователю 2–3 канала, на которые необходимо подписаться.
Пользователь подписывается на каналы и нажимает «Я подписался».
После нажатия бот проверяет подписку на каждый канал.
Бот должен учитывать только те каналы, к которым ему предоставлен необходимый доступ для проверки подписки.
Если доступ к каналу не предоставлен — этот канал автоматически исключается из проверки.
Если пользователь подписан на все доступные для проверки каналы — он становится участником розыгрыша.

2. База участников

Сохранять всех пользователей, которые нажали «Я подписался», даже если проверка не пройдена.
Хранить ID пользователя, дату участия и статус проверки.
Один пользователь может быть зарегистрирован только один раз.
Отображать актуальный счётчик участников прям в боте.

3. Управление

Администратор должен иметь возможность:

добавлять и удалять каналы;
менять каналы, необходимые для подписки;
управлять текстами сообщений и уведомлений;
видеть количество участников;
просматривать и выгружать базу;
запускать и завершать розыгрыш.

4. Нагрузка

Бот должен быть рассчитан на большое количество участников и одновременных запросов.
Проверка подписок и регистрация пользователей не должны приводить к зависаниям или потере данных.
Архитектура должна предусматривать возможность дальнейшего масштабирования при резком росте нагрузки.
